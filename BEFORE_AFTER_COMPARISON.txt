================================================================================
FIX 2: UNCERTAINTY-AWARE KNOCKOUTS
================================================================================

BEFORE:
  Rule: if PD >= 12% → AUTO-REFER

  Problem: Doesn't consider confidence level
           PD=0.120 ± 0.001 treated same as PD=0.120 ± 0.050

  Result: ~15-20% false positive knockouts

AFTER:
  Rule: if pd_low >= 12% → AUTO-REFER
        (Even best-case must be risky)

  Example: PD 4.16% (band: 2.35-5.96%)
           → pd_low = 2.35% < 12% → NOT referred
           → Detail shows band for transparency

  Benefit: False positives eliminated
           Only truly risky cases auto-referred
  Impact: -15% false positives, -10% review workload

================================================================================
IMPLEMENTATION DETAILS
================================================================================

Three focused code changes:

1. Addition of XGBoost importance to attribution
   └─ One data source: model.feature_importances_
   └─ One computation: weighted_rank = importance × abs(contribution)
   └─ One sorting change: sort by weighted_rank instead of abs(contribution)

2. Uncertainty band usage in knockouts
   └─ One parameter added: pd_low, pd_high
   └─ One logic change: use pd_low instead of pd_point
   └─ One message enhancement: show band in detail

3. Learned thresholds for Five C's
   └─ One new method: _get_learned_thresholds()
   └─ One caching mechanism: self._learned_thresholds
   └─ One data flow: fetch learned thresholds in _five_cs()

Total implementation: ~55 lines of focused, targeted changes
